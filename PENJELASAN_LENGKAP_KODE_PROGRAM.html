BAGIAN I: BEDAH KODE SERVER BACKEND PYTHON (server_guru/main.py)

Server backend bertugas sebagai pusat komputasi berat (heavy-duty computing), pemantauan perangkat keras, pencadangan otomatis (disaster recovery), dan sinkronisasi basis data real-time via Firebase Admin SDK.

3. Algoritma Pra-Pemrosesan Kontras CLAHE

def terapkan_clahe(gambar_rgb: np.ndarray) -> np.ndarray: # 1. Konversi ruang warna dari BGR/RGB ke CIELAB lab = cv2.cvtColor(gambar_rgb, cv2.COLOR_RGB2LAB) l_channel, a_channel, b_channel = cv2.split(lab) # 2. Terapkan CLAHE HANYA pada kanal L* (Luminansi/Kecerahan) clahe = cv2.createCLAHE(clipLimit=CLAHE_CLIP_LIMIT, tileGridSize=CLAHE_TILE_GRID) l_clahe = clahe.apply(l_channel) # 3. Gabungkan kembali dengan kanal warna a* dan b* asli (Mencegah distorsi warna kulit) lab_clahe = cv2.merge((l_clahe, a_channel, b_channel)) return cv2.cvtColor(lab_clahe, cv2.COLOR_LAB2RGB)

Penjelasan Ilmiah: Penerapan CLAHE pada kanal $L^*$ (Luminansi) bertujuan meningkatkan ketajaman fitur wajah di area berbayangan tanpa mengubah komponen kromatik ($a^*$ dan $b^*$). Hal ini mencegah terjadinya pergeseran warna kulit (hue shift) yang dapat mengacaukan model pengenalan biometrik.

4. Rumus Cosine Similarity untuk Pencocokan Biometrik

Untuk mengukur kemiripan antara dua vektor wajah berdimensi 512, digunakan rumus Cosine Similarity:

def hitung_cosine_similarity(vektor_a: np.ndarray, vektor_b: np.ndarray) -> float: dot_product = np.dot(vektor_a, vektor_b) norma_a = np.linalg.norm(vektor_a) norma_b = np.linalg.norm(vektor_b) if norma_a == 0 or norma_b == 0: return 0.0 return float(dot_product / (norma_a * norma_b))

Secara matematis:

$$\text{Cosine Similarity}(\vec{A}, \vec{B}) = \frac{\vec{A} \cdot \vec{B}}{\|\vec{A}\| \|\vec{B}\|} = \frac{\sum_{i=1}^{512} A_i B_i}{\sqrt{\sum_{i=1}^{512} A_i^2} \sqrt{\sum_{i=1}^{512} B_i^2}}$$

Nilai berada pada rentang $[0.0 \dots 1.0]$. Jika nilai $\ge 0.80$, identitas siswa dinyatakan terkonfirmasi.

5. Endpoint Utama Presensi Multi-Wajah (/api/scan-attendance)

  • Semaphore Locking (asyncio.Semaphore(2)): Membatasi maksimal 2 pemrosesan AI bersamaan agar memori RAM VPS 4GB tidak mengalami Out-of-Memory (OOM).
  • Deteksi Multi-Wajah: Memindai seluruh wajah dalam gambar secara simultan menggunakan YOLO, memotong setiap kotak dengan tambahan 15% padding.
  • Ekstraksi & Pencocokan: Mengekstrak vektor tiap potongan wajah dan mencocokkannya dengan database in-memory siswa.
  • Real-Time Firestore Update: Mencatat seluruh siswa yang hadir secara atomik ke koleksi absensi_harian/{YYYY-MM-DD} dengan opsi merge=True.

BAGIAN II: BEDAH KODE CLIENT MOBILE FLUTTER (lib/core/ai/)

Aplikasi mobile dirancang dengan filosofi On-Device AI & Offline-First, di mana seluruh proses inferensi dan pencocokan biometrik berlangsung lokal di dalam prosesor ponsel.

1. face_detector_service.dart (Deteksi Wajah Lokal On-Device)

  • Pustaka: google_mlkit_face_detection
  • Keunggulan: Berjalan langsung di atas akselerasi perangkat keras ponsel (NPU/GPU Neural Networks API) dengan waktu eksekusi super cepat (~20 ms).
  • Konfigurasi:
    FaceDetectorOptions( enableContours: false, // Kontur dimatikan untuk menghemat daya enableLandmarks: true, // Deteksi titik mata, hidung, mulut performanceMode: FaceDetectorMode.accurate, // Mode akurasi tinggi minFaceSize: 0.1, // Wajah terdeteksi minimal 10% dari layar )

2. face_embedding_service.dart (Ekstraksi Biometrik MobileFaceNet)

  • Model: mobilefacenet.tflite (Ukuran sangat ringkas, hanya ~4.8 MB).
  • Tahapan Pemrosesan Citra:
    1. Crop & Padding: Memotong area wajah dengan tambahan margin 15% agar kontur dahi dan rahang tidak terpotong.
    2. Resizing: Mengubah ukuran matriks citra menjadi resolusi standar $112 \times 112$ piksel.
    3. Normalisasi Piksel: Menormalkan nilai piksel RGB $[0 \dots 255]$ ke rentang $[-1.0 \dots 1.0]$ menggunakan rumus: $$\text{Pixel Norm} = \frac{\text{Pixel} - 127.5}{127.5}$$
    4. Inferensi Tensor: Memasukkan tensor bentuk $[1, 112, 112, 3]$ ke interpreter TFLite untuk menghasilkan 128 angka embedding.
    5. Normalisasi Vektor $L_2$: Menormalkan panjang vektor menjadi 1 unit agar perbandingan jarak Euclidean setara dengan perbandingan sudut Cosine: $$\vec{V}_{\text{norm}} = \frac{\vec{V}}{\|\vec{V}\|_2} = \frac{\vec{V}}{\sqrt{\sum_{i=1}^{128} V_i^2}}$$

3. face_matching_service.dart (Pencocokan Euclidean Distance)

File ini bertindak sebagai mesin penentu kehadiran di smartphone:

// Parameter Kalibrasi Biometrik static const double BATAS_TERIMA = 0.45; // Ambang batas penerimaan identitas static const double SELISIH_MINIMAL = 0.06; // Gap pemisah anti-ambiguitas wajah mirip static double euclideanDistance(List<double> a, List<double> b) { double sum = 0.0; for (int i = 0; i < a.length; i++) { double diff = a[i] - b[i]; sum += diff * diff; } return sqrt(sum); }
  • Jarak Euclidean: Semakin kecil nilai jarak, semakin mirip kedua wajah ($D < 0.45 \rightarrow$ Cocok).
  • Anti-Ambiguity Margin Gap: Jika wajah seorang siswa mirip dengan dua kandidat berbeda di database (misal dua bersaudara), sistem mensyaratkan selisih jarak terbaik dan kedua terbaik minimal $\Delta \ge 0.06$. Jika selisihnya $< 0.06$, sistem menganggapnya ambigu dan menolak pencocokan demi mencegah salah absensi.
  • Unique Assignment: Satu siswa terdaftar hanya dapat dicocokkan dengan 1 wajah fisik dalam satu frame untuk mencegah absensi ganda.

4. face_database_service.dart (Sinkronisasi Dual-Tier Hive + Firestore)

  • Tingkat 1 (Lokal): Menyimpan vektor embedding siswa di box Hive face_embeddings_cache (penyimpanan binary noSQL super cepat di memori HP).
  • Tingkat 2 (Cloud): Menyinkronkan dokumen ke Firestore pada koleksi face_embeddings/{NIM}.
  • Strategi Sinkronisasi Kelas: Fungsi syncByClass(classId) hanya mengunduh data siswa yang terdaftar pada kelas yang sedang diajar guru, menghemat konsumsi bandwidth hingga 95%.

5. RegisterStudentScreen.dart (Registrasi Cerdas)

  • Dominant Face Selector: Mengurutkan wajah terdeteksi berdasarkan luas area ($W \times H$). Wajah terbesar dipilih sebagai wajah siswa pendaftar.
  • Noise Filtering: Objek atau wajah kecil di latar belakang yang luasnya $< 35\%$ dari wajah utama otomatis diabaikan, sehingga pengguna tidak perlu mendekatkan wajah secara berlebihan saat mendaftar.
  • Dual-Server Fallback: Fungsi _syncToServer() secara otomatis mencoba mengirim data ke port 8001; jika gagal, beralih ke port 8000 secara asinkron di latar belakang tanpa mengganggu tampilan pengguna.

6. AttendanceScreen.dart (Scanner Otomatis Hands-Free)

  • Continuous Auto-Scan: Menggunakan Timer.periodic(Duration(milliseconds: 1600)) yang secara otomatis mengambil frame dan memproses deteksi setiap 1,6 detik tanpa perlu menekan tombol jepret.
  • Viewfinder Luas: Kotak panduan kamera dirancang dengan lebar 92% layar dan tinggi 380 piksel, dilengkapi garis animasi laser hijau neon yang bergerak naik-turun.
  • Deteksi Multi-Wajah Simultan: Mampu mengenali lebih dari satu siswa dalam 1 kali jepretan frame. Jika ada 2 siswa yang lewat bersamaan, sistem memunculkan banner pop-up:
    "🎉 [Nama 1] & [Nama 2] (Hadir)!"
  • Umpan Balik Haptic: Ponsel bergetar lembut (HapticFeedback.mediumImpact()) seketika wajah dikenali sebagai sinyal sukses bagi guru.

BAGIAN III: RINGKASAN INTEGRASI SISTEM UNTUK SIDANG SKRIPSI

Pertanyaan Kunci Penguji: "Bagaimana Alur Integrasi Antara Mobile dan Server?"

Jawaban Ilmiah:

Sistem ini menerapkan paradigma Hybrid Edge-Cloud Biometrics:

  • Pada Sisi Client (Edge Mobile): Google ML Kit dan MobileFaceNet melakukan inferensi berkecepatan tinggi (~50 ms) langsung di prosesor ponsel menggunakan data cache lokal Hive, sehingga proses absensi di kelas 100% mandiri, bebas lag, dan tidak bergantung pada sinyal internet.
  • Pada Sisi Server (Cloud Backend): FastAPI di VPS port 8001 bertindak sebagai pengawas keamanan, menjalankan model deteksi beresolusi tinggi (YOLOv26/YOLOv8 + ArcFace 512-d), melakukan backup berkala seluruh basis data ke file JSON, dan mengirimkan email darurat jika terjadi anomali sistem.
  • Pada Sisi Pusat Sinkronisasi (Firebase Firestore): Menghubungkan semua data secara real-time sehingga riwayat kehadiran siswa yang dipindai guru di kelas dapat langsung dipantau oleh admin sekolah dan siswa secara transparan.
